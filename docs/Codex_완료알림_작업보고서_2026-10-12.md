## 원인과 변경

이전 버전은 완료 알림을 Claude에만 연결했다. Codex 파서의 Sessions가 비어 있었고, RefreshData는 속도 표시가 켜진 경우에만 Codex 지표를 읽었으며, 완료 알림 검사·카드 제목·색상이 Claude로 고정되어 있었다.

- UsageWidget.cs: Codex 작업 종료·중단 정보를 SessionTurn으로 제공하고 완료 기록 최대 32개를 유지한다. 다음 작업이 시작되어도 직전 완료를 폴링에서 놓치지 않는다.
- Codex 완료 알림을 기존 알림 설정·소리·깜박임·10초 카드·최대 4개 스택에 연결한다. AI별 카드 제목과 색상을 사용한다. 프로젝트 폴더명과 첫 사용자 요청에서 제목을 가져온다.
- 완료 알림이 켜져 있으면 속도 표시나 Codex 사용량 표시가 꺼져 있어도 Codex 기록을 조회한다. 기존 Claude 알림과 같은 정책이다.
- 정상 완료만 알린다. 실행 중, 중단, 방치, 위젯 실행 이전 완료, 5분 이상 지난 완료, 미래 시각은 제외한다. 세션 경로와 시작시각·AI의 조합으로 중복을 막는다.
- CodexMetricsTests.cs: 완료 정보·중복·시작 전 이력·중단·보조 세션·다음 작업 시작 관련 회귀검증 추가.
- NotificationIntegrationTests.cs: 실제 WidgetForm.RefreshData 경로에서 카드 생성·중복 억제·중단 억제 검증. 개인 기록 대신 독립 임시 로그를 사용한다.
- README.md와 배포 전용 안내를 갱신하고 배포 ZIP을 다시 생성했다.

## 검증과 검토

- build.ps1: 컴파일 성공.
- test.ps1 -CodexSessions %USERPROFILE%\.codex\sessions: 26개 통과.
- NotificationIntegrationTests를 별도 main으로 컴파일하고 실행: 속도·Codex 표시를 꺼도 정상 완료 카드 1개 생성, 반복 조회 시 추가 카드 없음, 중단 시 카드 없음. 카드 Visible 상태와 제목도 확인했다.
- 동일 카드의 DrawToBitmap 렌더를 시각 확인했다. 파란 Codex 완료 제목·5초 작업시간·세션 제목·프로젝트가 표시되었다. 상시 위젯의 화면 캡처나 실제 사용자 작업 완료를 관찰한 것으로 표현하지 않는다.
- Computer Use는 toolwindow를 창 목록에 반환하지 않아 실제 카드 캡처는 수행하지 못했다.
- 초기 렌더 검증 재컴파일은 실행 중인 검증 exe의 잠금으로 실패했다. 다른 출력 exe명으로 다시 컴파일·실행해 성공했다.
- adversarial-review: 실제 변경과 호출 경로를 검토했다. 배포를 막는 critical/high 발견 없음. 기존 Claude 경로와 제외 조건을 유지하며 로컬 기록은 읽기만 한다.
- git diff --no-index --check: 공백 오류 없음.
