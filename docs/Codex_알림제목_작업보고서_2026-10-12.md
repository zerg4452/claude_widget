## 원인과 수정

실제 Codex 데스크톱 로그에는 사용자 요청이 response_item/message/role=user/content/input_text로 기록되었다. 이전 구현은 event_msg/user_message만 처리해 제목이 비어 있었고 ShowToast의 프로젝트 폴더명 fallback으로 design_refs가 표시되었다.

UsageWidget.cs에서 실제 사용자 메시지 형식을 지원한다. 메타데이터의 user.text와 turn_id를 확인하고 AGENTS·환경·열린 페이지·질문 답변 주입 내용은 제외한다. 메타데이터가 없는 일반 사용자 메시지도 지원한다. 작업 시작마다 제목을 초기화해 각 작업의 첫 실제 요청을 표시한다. 줄바꿈·연속 공백을 정리하고 80자 제한을 유지한다.

## 검증과 검토

- build.ps1 컴파일 성공.
- test.ps1 -CodexSessions: 29개 통과. 실제 앱 로그에서 알림 제목이 추출되는 것까지 검증했다.
- 추가 회귀검증: 데스크톱 메시지 형식, AGENTS·열린 페이지·질문 답변 제외, 제목의 작업별 초기화, 과거 turn_id 메시지 제외.
- NotificationIntegrationTests를 실제 앱의 response_item 형식으로 갱신해 실제 RefreshData → ShowToast 경로의 카드 제목이 사용자 요청과 같음을 확인한다.
- adversarial-review: 실제 diff와 메시지 입력·완료 보존·카드 fallback 경로 검토. critical/high 발견 없음. 보조 세션 제외와 기존 알림 제외 조건 유지.
- 조회 대상 세션 수·날짜·80자 제목 제한은 기존대로 유지한다.
